# Почта Wimli

Реализованы подтверждение адреса и восстановление пароля покупателей и продавцов,
повторная отправка раз в минуту, уведомления продавцу о новом заказе и обеим сторонам
об изменении статуса заказа. Письма сохраняются в PostgreSQL и отправляются через
SMTP с проверкой TLS-сертификата. Секреты берутся только из окружения.

## Amvera

В переменных сервиса MP установить MAIL_SERVER, MAIL_PORT, MAIL_USERNAME,
MAIL_PASSWORD (пароль приложения), MAIL_DEFAULT_SENDER, PUBLIC_BASE_URL.
Для Mail.ru: smtp.mail.ru, порт 465, MAIL_USE_SSL=True, MAIL_USE_TLS=False.
Для STARTTLS: порт 587, MAIL_USE_SSL=False, MAIL_USE_TLS=True.
Адрес отправителя должен быть разрешён почтовым провайдером.
PUBLIC_BASE_URL — доверенный HTTPS-адрес сайта, сейчас https://wimli.ru.
Ссылки не строятся из HTTP Host посетителя.

Docker запускает db-init, который создаёт три новые таблицы без изменения старых.
Gunicorn загружает gunicorn.conf.py и запускает очередь в каждом worker. Задания
забираются атомарно; после перезапуска незавершённое задание доступно через 10 минут.
До шести попыток с увеличением интервала. Состояния: pending, sending, sent,
failed, expired. SMTP не гарантирует exactly-once: при обрыве сразу после приёма
письма сервером возможен повтор. Message-ID остаётся прежним.

Проверить SMTP без отправки: `flask --app wsgi mail-check`.
Одна партия вручную: `flask --app wsgi mail-deliver`.
Внешний worker может вызывать эту команду по расписанию; тогда отключить
MAIL_WORKER_ENABLED. Для локального Flask dev-server отправлять этой командой.

Если SMTP не настроен, формы честно сообщают о недоступности; обязательное
подтверждение не включается для новых регистраций. Старые аккаунты сохраняют вход.
EMAIL_VERIFICATION_REQUIRED=False отключает обязательность для последующих регистраций.
Изменение email сбрасывает подтверждённость; ссылки привязаны к адресу, роли,
идентификатору пользователя и текущему хэшу пароля. GET не расходует ссылку.
Токены живут 30 минут; погашение и изменение аккаунта выполняются одной транзакцией.
Для этого PostgreSQL-соединения остаются в READ COMMITTED, без прежнего AUTOCOMMIT.
Отправленные тела писем удаляются из очереди; токены хранятся в виде SHA-256.
Не включать логирование URL запросов подтверждения/восстановления на внешнем прокси.

## Проверка

`python -m unittest discover -s tests -v`

Тесты используют изолированную SQLite БД и подменённый SMTP: реальные письма
пользователям не отправляются. Проверка реальной доставки во входящие требует
контрольного письма через настроенный production SMTP.
